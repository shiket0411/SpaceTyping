# テストとバランス計測

ブラウザを開かずに、ゲーム本体を Node.js 上でそのまま動かして検証します。
`tools/harness.js` が canvas・localStorage・requestAnimationFrame を差し替え、
`js/*.js` を無改変で読み込みます。**本番コードにテスト専用の分岐は一切ありません。**

必要なもの: Node.js 18 以降のみ（依存パッケージなし）。

---

## クイックスタート

```bash
node tools/test.js            # 正当性テスト（約10秒）
node tools/balance.js clear   # 難易度ごとのクリア率（数分）
```

`tools/test.js` は全通過で終了コード 0、失敗があれば 1 を返します。CI に載せられます。

---

## 1. 正当性テスト `tools/test.js`

```bash
node tools/test.js [all|romaji|play|render|ui|controls|jitter]
```

引数なしは `all`。個別に走らせると数秒で終わります。

| スイート | 何を見るか |
|---|---|
| `romaji` | かな→ローマ字の受理判定。`しゅっぱつ` を `shuppatsu`/`syuppatu`/`shixyuppatsu` などで打てるか、逆に IME 同様 `てんのう`←`tennou` を弾くか。単語バンクの階層ごとの語数も検査する |
| `play` | 各難易度でミッションが例外なく完走するか。撃破・得点・打鍵が成立しているか。セーブの保存/読み直しの一致。装備生成物の健全性 |
| `render` | canvas 呼び出しの検証。**NaN 座標・不正な色・不正なフォント**を検出する。実ブラウザでは目視しないと気づけない類のバグをここで捕まえる |
| `controls` | 操作系の回帰。TAB でのモード切替、SHIFT+TAB での目標送り、SPACE が打鍵に使えること、オーバードライブの発動効果と必要量の逓増、ミス硬直の可視化 |
| `ui` | 画面遷移の回帰。補給ドックでの購入・売却が格納庫へ反映されるか、売却済みアイテムを複製できないか、拡張スロットを選んで装備できるか、スコア記録が難易度をまたいで見えるか、セーブ失敗を検知できるか |
| `jitter` | 敵の座標が1フレームで飛んでいないか。移動パターンごとに「最大1フレーム移動量 ÷ 平均」を測り、8倍を超えたらワープとみなす |

### 出力の読み方

```
  ok   受理 しゅっぱつ <- shixyuppatsu
  FAIL 拒否 ぎんが <- ginka
```

`FAIL` の行には期待と実際の差分が付きます。最後に総括と終了コードが出ます。

`render` が失敗した場合は、問題のあった呼び出しが最大12件まで列挙されます。

## 2. バランス計測 `tools/balance.js`

```bash
node tools/balance.js <サブコマンド> [引数]
```

**すべてシード固定**です。同じ引数なら装備の乱数も含めて完全に同じ結果が出ます。
パラメータを変えた前後で比較するときは、この再現性が効きます。

| サブコマンド | 用途 | 目安の所要時間 |
|---|---|---|
| `clear [試行回数] [ミス率]` | 難易度ごとのクリア率。**最も重要な指標** | 16回で約4分 |
| `style [秒数]` | 「篭る/切り替える/攻め続ける」3種の立ち回り比較 | 数秒 |
| `energy [試行回数]` | 迎撃エネルギーの収支。攻撃モードに居座った場合との比較 | 十数秒 |
| `boss [試行回数]` | 各ボスの所要単語数と設計目標の対比 | 数秒 |
| `laser` | 圧力に対するレーザーの発射間隔と毎秒ダメージ（式から算出、実測なし） | 即時 |
| `gear [試行回数]` | レアリティ別の装備性能（中央値） | 数秒 |
| `sweep NAME=a,b,c [試行回数]` | パラメータを振ってクリア率を比較 | 値の数×数分 |

### `clear` の読み方

```
条件                        クリア率  平均最低HP  被弾  攻撃滞在  最大圧力  平均秒
s4/ACE       LV24 Rare        16/16         82%    14       79%       61%     122
s8/NIGHTMARE LV30 Leg x4       4/16         26%    45       91%       76%     265
```

- **クリア率** — 到達させたい水準の主指標
- **平均最低HP** — クリアしていても余裕があったのか、ギリギリだったのか
- **攻撃滞在** — 攻撃モードにいた時間の割合。低いほど防御に追われている
- **最大圧力** — 戦域圧力のピーク。100% に張り付くならレーザーが猛威を振るっている

条件名の `x4` は装備4スロット構成です。**スロットを5つ埋めるかどうかで体感が大きく変わる**ため、
比較用に両方を並べてあります（下の「調整の基準値」参照）。

### `sweep` の使い方

```bash
node tools/balance.js sweep LASER_BASE=4,5,7 8
```

`js/game.js` の `var LASER_BASE = 5;` をメモリ上で 4 / 5 / 7 に差し替えて比較します。
**ソースファイルは一切書き換えません。**差し替え可能なのは `js/game.js` 内の
`var 大文字名 = 数値;` 形式の定数です（一覧は [BALANCE.md](BALANCE.md)）。

存在しない名前を指定すると即座にエラーになります。

## 3. 仮想プレイヤーについて

計測に使う仮想プレイヤーの挙動は `tools/sim.js` にあります。

- 打鍵速度は既定 **5.75打鍵/秒（約69WPM）**。`kps` で変更可能
- ローマ字の入力経路は**常に先頭候補（最短経路）**を選ぶ。人間は入力方式が一貫しているため。
  ランダムに選ばせると `shi`/`si` のような長い経路を踏んで所要打鍵が2割ほど膨らむ
- 立ち回りは3種
  - `balanced` — エネルギーが30%を切ったら迎撃へ、90%を超えたら攻撃へ（標準的な上手いプレイ）
  - `camp` — 迎撃モードに篭る
  - `rush` — 攻撃モードに固定する
- ミス率の既定は 0%。**調整時の基準がこの条件**なので、下の基準値もミス率0%で計測しています

人間はこれより不規則ですが、パラメータ変更の影響を比較する用途では十分に安定しています。

## 4. 調整の基準値

現在のバランスの到達点です。`node tools/balance.js clear 16` で再現できます。
（打鍵5.75/秒・ミス率0%・シード固定・各16回）

| 条件 | クリア率 | 平均最低HP |
|---|---|---|
| s1/NOVICE (LV5 Common) | 16/16 | 98% |
| s1/PILOT (LV8 Uncommon) | 16/16 | 99% |
| s3/PILOT (LV16 Uncommon) | 16/16 | 100% |
| s4/CADET (LV20 Uncommon) | 16/16 | 100% |
| s4/ACE (LV24 Rare) | 16/16 | 90% |
| s6/VETERAN (LV30 Epic — 装備不足) | 7/16 | 45% |
| s6/VETERAN (LV34 Legendary) | 16/16 | 100% |
| s8/NIGHTMARE (LV30 Legendary ×5) | 7/16 | 43% |
| s8/NIGHTMARE (LV70 Legendary) | 15/16 | 80% |
| s8/SINGULARITY (LV30 Legendary ×5) | 4/16 | 22% |
| s8/SINGULARITY (LV70 Legendary) | 10/16 | 61% |
| s8/NIGHTMARE (LV30 Legendary ×4) | 3/16 | 17% |
| s8/SINGULARITY (LV30 Legendary ×4) | 1/16 | 4% |

各セルは16回の二項試行なので、**±2程度は統計誤差**です。1〜2の差で結論を出さないでください。

設計意図:

- **序盤〜中盤（NOVICE〜ACE）は確実にクリアできる。** ここで死ぬなら調整ミス
- **VETERAN 以降は装備が要求される。** LV30/Epic で 7/16、LV34/Legendary で 16/16 という差が、
  ハクスラとしての「farm して戻る」動機になっている
- **NIGHTMARE は何とかクリアできる水準**（装備4個で 3/16、5個で 7/16）
- **SINGULARITY は壁**（装備4個で 1/16）。装備を極めれば手が届く（LV70 で 10/16）

立ち回りの差も設計の要です。`node tools/balance.js style` で確認できます。

| 立ち回り | 最終圧力 | 撃破 | 被弾 | 到達ウェーブ |
|---|---|---|---|---|
| 迎撃モードに篭る | 100% | 0 | 35 | 1 で停滞 |
| エネルギーで切替 | 27% | 26 | 4 | 6 |
| 攻撃モードに固定 | 12% | 30 | 117 | 6 |

## 5. よくある落とし穴

**計測がぶれる**
装備は5つのスロットにランダムなアフィックスが乗るため、試行回数が少ないと
パラメータの効果とノイズを区別できません。過去に「無関係な変更でクリア率が 0/10 → 4/10 に動く」
という事故がありました。**必ずシード固定のまま試行回数を10以上**にしてください。

**装備スロットの数**
4個構成と5個構成でクリア率が2倍近く変わります。比較するときは条件を揃えてください。

**ミス率**
ミスは硬直（0.26秒 × 難易度係数）とコンボ消滅を招き、VETERAN 以上ではエネルギーも減ります。
ミス率5%でも体感はかなり変わるので、基準値と比べるときは 0% のままにしてください。

**`godMode` / `toBoss`**
`tools/sim.js` の `runMission` にこれらを渡すと毎フレームHPが全回復します。
被弾数やレーザー着弾数だけを数えたいときに使うもので、**クリア率の計測には使えません。**
